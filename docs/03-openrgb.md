# 3. OpenRGB support

The controller lives in `openrgb/Controllers/AULAF108ProController`. It works only with the custom firmware from this
project (stock firmware has no direct RGB mode), over the USB cable and over the 2.4G dongle.

## Zones in OpenRGB

| Zone | LEDs | Type |
|---|---|---|
| Keyboard | 104 keys | matrix |
| Arrow bar | 5 segments above the arrow keys, left to right | linear |
| Left strip | 7 LEDs, far edge to near edge | linear |
| Right strip | 7 LEDs, near edge to far edge | linear |

LEDs 140 to 146 and about 20 cells of the key matrix do not exist physically and are not exposed.
The arrow bar has red and green swapped in hardware (GRB); the controller compensates, see `AULAF108ProLayout.h`
(`AULA_ARROW_BAR_SWAP_RG`, `AULA_KEYS_SWAP_RG`, `AULA_SIDES_SWAP_RG`).

Modes: Direct (OpenRGB controls everything) and "Keyboard's own lighting" (stock lighting). If OpenRGB is closed or the
cable is unplugged, the keyboard returns to its own lighting by itself after about 1.3 seconds.

## Two transports

| | Cable | 2.4G dongle |
|---|---|---|
| USB ID | 0C45:800A, interface 3, usage page 0xFF13 | 05AC:024F, interface 3, usage page 0xFF60 |
| Detector name | "AULA F108 Pro" | "AULA F108 Pro (2.4G)" |
| Speed | full frames at normal rates | radio limit, roughly 100 to 125 packets per second, round trip about 14 ms |

Over 2.4G a full 147 LED frame takes many packets, so fast effects look choppy and have latency. The controller sends only
the blocks that changed. Static colors, slow effects and lighting that follows the screen slowly are fine.

## Option A: build OpenRGB yourself (recommended)

The controller was written against OpenRGB master at commit `3021bc4f930c74c867a8f47d425031f55e47ef43`
(October 2026). Newer versions may need small API changes.

1. Clone OpenRGB: `git clone https://gitlab.com/CalcProgrammer1/OpenRGB` and check out the commit above if you want an exact match.
2. Copy `openrgb/Controllers/AULAF108ProController` into `OpenRGB/Controllers/`. Do not edit the project file: qmake collects
   everything under `Controllers` by wildcard.
3. Build following `Documentation/Compiling.md` in the OpenRGB repository.

Windows, what the author used: Qt 6.8.3 (msvc2022_64), Visual Studio 2022 Build Tools (C++ x64), jom. In a prompt with the
MSVC environment and Qt `bin` in PATH:

```
qmake OpenRGB.pro CONFIG-=debug_and_release CONFIG+=release
jom -j 16
windeployqt --no-translations --no-system-d3d-compiler --no-compiler-runtime --no-opengl-sw --no-network .\release\
```

Result: `release\OpenRGB.exe`. If your OpenRGB build also needs `Qt6Core5Compat.dll` and `Qt6OpenGL.dll`, copy them from Qt's `bin`.

Linux: `mkdir build && cd build && qmake ../OpenRGB.pro && make -j`. You also need a udev rule so that your user can open the hidraw
devices (the stock OpenRGB rules do not list these IDs), for example in `/etc/udev/rules.d/61-aula-f108.rules`:

```
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="0c45", ATTRS{idProduct}=="800a", TAG+="uaccess"
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="05ac", ATTRS{idProduct}=="024f", TAG+="uaccess"
```

then `sudo udevadm control --reload && sudo udevadm trigger`. The Linux build was not tested by the author.

## Option B: replace an installed OpenRGB

If you already run OpenRGB (possibly as a Windows service) and want to swap in your own build, use
`openrgb/install_openrgb.ps1` from an administrator PowerShell. It stops the service and processes, backs up the install folder,
copies your build over it (keeping `plugins`, `service_config` and your settings) and starts the service again.
Edit the parameters at the top of the script first. To undo: `openrgb/restore_openrgb.ps1`.

## Disable the Keychron detector

OpenRGB has a detector for a Keychron device that uses the same dongle ID (05AC:024F). It would talk to the AULA dongle with
a different protocol. In OpenRGB, Settings, Supported Devices, disable "Keychron Gaming Keyboard 1" (or set it to false
in `OpenRGB.json`, section `Detectors`).

## Plugins and the rest

Nothing special: it is a normal OpenRGB build, plugins work as usual. Close the AULA driver software while using OpenRGB,
two programs writing to the same device will fight.

## Regenerating the layout

`AULAF108ProLayout.h` is generated by `openrgb/gen_layout.py` from `openrgb/keymap.json` (key to LED index map). You only need this
to rename keys or change the channel order.
